## Changelog

## 한국어

> **공식 서버에서 방을 열려면 방장 동의가 필요합니다.** 원본 1.5.1부터 시그널링 서버가 방장의 동의 기록을 요구합니다. 업데이트 후 처음 한 번 `/p2p consent`로 문구를 읽고 직접 동의해 주세요(자동으로 동의하지 않습니다). 가맹점은 공개 방을 열 때만 필요합니다. Java 21.0.13 / 25.0.5 이하처럼 보안 취약점(CVE-2026-91403)이 패치되지 않은 Java에서는 방이 열리지 않을 수 있습니다 — `/p2p java`로 확인하세요.

원본 instant-p2p 모드 **1.5.1**, 가맹점 모드는 **F4.0.2** 기준입니다.

### 추가
- **원본 1.5.1 / 가맹점 F4.0.2 대응**: 방장 연결에 클라이언트 정보를 싣고, 공개 방일 때 방 정보·밴 목록·접속자 알림·방 기록 신호(30초 하트비트)·서버 알림을 처리합니다. 서버가 거부하면 재시도를 멈추고 이유를 관리자에게 알립니다. 서버가 공개 방을 받지 않는 동안(점검 등)에는 10분마다 한 번만 상태를 확인합니다.
- **`/p2p consent`**: 방장 동의 문구를 보고 직접 동의합니다(공식 서버, 가맹점 공개 방). 가맹점은 동의가 없으면 초대 코드 방으로만 엽니다.
- **`/p2p java`**: Java 취약점(CVE-2026-91403) 점검. 패치 안 된 Java면 방 열기를 막고, 운영자가 직접 `fix`나 `ignore`를 고릅니다. 자동으로 바꾸지 않습니다.
- **`/p2p ban-ip` · `pardon-ip` · `ban-list`**: 플러그인 자체 IP 밴 목록(프록시·중계 강제 접속자용). 중계 접속자는 계정으로 막고(원래 IP는 어디에도 남지 않습니다), 직결 접속자는 주소로 막으며 Paper·Spigot·Fabric에서는 바닐라 `ban-ip`에도 같이 올립니다.
- **다이얼로그**: 가맹점 약관·동의 문구를 MC 1.21.6+ (Paper 1.21.7+) 플레이어에게 스크롤되는 창으로 보여 줍니다.
- **가맹점 F4 공개 방**: F4 클라이언트의 방 목록에 보이도록 로비 태그를 F4 방식으로 계산합니다.

### 개선·수정
- **원본 1.5.x부터 중계 접속자의 주소가 접속마다 계속 바뀌는 것을 IP 밴이 유동적으로 따라갑니다.** 원본 1.5.x 클라이언트는 접속할 때마다 중계 할당을 새로 잡아 서버가 보는 합성 주소가 매번 달라지므로, 중계 접속자는 **계정에 연결해서** 막습니다(주소가 바뀌어도 그 계정만 계속 막히고 원래 IP는 어디에도 남지 않습니다). 바닐라 `/ban-ip`로 막은 중계 접속자도 같은 계정이 새 주소로 들어오면 막습니다.
- 보안·안정성: 사설망·링크 로컬 후보 주소 거부, 깨진 패킷 방어, UDP 폭주 방어, 출발지별 연결 상한과 업로드 제한, 재접속 백오프 개선.
- 서버를 며칠씩 켜 둘 때를 위한 연결 유지(원본 1.5.1): 공인 주소 변화 감시(30초), 중계 경로 점검과 할당 재설정(60초), TURN 권한·채널 상한, QUIC 주소 검증(Retry).
- Velocity에서 접속자가 나갈 때 `Connection reset` 오류를 줄였습니다.
- 모드 클라이언트에 보내는 방 등급 목록을 64명으로 제한했습니다.

### 알아 둘 점
- 중계 강제 접속자의 서버 쪽 주소는 접속할 때마다 바뀝니다. 주소가 고정돼 있어야 하는 기능은 기대하지 말고, 밴은 `/p2p ban-ip <플레이어>`를 쓰세요.
- 새로 생기는 파일(데이터 폴더): `consent.json`, `p2p-bans.json`, `relay-links.json`(실제 IP는 담지 않습니다).
- 원본 클라이언트의 **채팅 자동 검사와 월드 이벤트 기록은 서버 통합판에서 하지 않으며, 유저 신고 때 시그널링 서버가 묻는 증거(앞뒤 채팅 등)에도 답하지 않습니다.**
- Velocity는 접속자가 나간 뒤 15~30초 세션을 들고 있을 수 있습니다. `velocity.toml`의 `kick-existing-players = true`로 두면 재접속이 바로 됩니다.

**업데이트:** jar만 바꾸고 재시작하면 됩니다. 로그인 정보·초대 코드·설정은 그대로 이어집니다. 공식 서버를 쓰는 경우 `/p2p consent`를 한 번 해 주세요.

## English

> **Opening a room on the official server now requires the host's consent.** Since the original 1.5.1, the signaling server requires a consent record from the host. After updating, run `/p2p consent` once, read the text and agree yourself (it is never accepted automatically). On the franchise server it is only needed for public rooms. On a Java that is not patched for CVE-2026-91403 (e.g. 21.0.13 / 25.0.5 and older) the room may not open — check with `/p2p java`.

Targets the original instant-p2p mod **1.5.1** and the franchise mod **F4.0.2**.

### Added
- **Support for original 1.5.1 / franchise F4.0.2**: the host connection carries client info, and for public rooms it sends room info, the ban list, join notices, a room-log signal (30-second heartbeat) and handles server notices. When the server refuses it stops retrying and tells the admins why. While the server is not accepting public rooms (maintenance etc.) it only rechecks every 10 minutes.
- **`/p2p consent`**: read the host consent text and agree yourself (official server, franchise public rooms). Without it, the franchise server opens an invite-code room only.
- **`/p2p java`**: Java vulnerability (CVE-2026-91403) check. On an unpatched Java it blocks opening rooms; the operator chooses `fix` or `ignore`. Nothing is changed automatically.
- **`/p2p ban-ip` · `pardon-ip` · `ban-list`**: the plugin's own IP ban list (for proxies and relay-forced guests). Relay guests are banned by account (their real IP is stored nowhere), direct guests by address; on Paper, Spigot and Fabric direct bans are also added to the vanilla `ban-ip`.
- **Dialogs**: the franchise terms and consent texts are shown as a scrollable window on MC 1.21.6+ (Paper 1.21.7+).
- **Franchise F4 public rooms**: the lobby tag is computed the F4 way so rooms appear in the F4 client's list.

### Improvements & fixes
- **IP bans now follow the ever-changing address of relay guests (original 1.5.x).** The original 1.5.x client allocates a fresh relay allocation on every connection, so the synthetic address the server sees differs on each join; relay guests are therefore banned **by account** (only that account stays blocked whatever address it gets; the real IP is stored nowhere). A relay guest banned with vanilla `/ban-ip` is also blocked when the same account returns with a new address.
- Security and stability: rejects private-network / link-local candidate addresses, malformed-packet protection, UDP flood protection, per-source connection limits and upload rate limit, better reconnect backoff.
- Long-uptime resilience (original 1.5.1): public-address re-check (30 s), relay path check with re-allocation (60 s), TURN permission/channel caps, QUIC address validation (Retry).
- Fewer `Connection reset` errors logged by Velocity when a guest leaves.
- The room rank list sent to the mod client is capped at 64 entries.

### Notes
- The server-side address of a relay-forced guest changes on every connection. Do not rely on features that need a stable address; use `/p2p ban-ip <player>` to ban them.
- New files (data folder): `consent.json`, `p2p-bans.json`, `relay-links.json` (no real IPs).
- The original client's **automatic chat scanning and world-event logging are not done by the server edition, and it does not answer the signaling server's report-evidence queries.**
- Velocity may keep a session for 15–30 seconds after a guest leaves. Set `kick-existing-players = true` in `velocity.toml` so a reconnect goes through immediately.

**Updating:** replace the jar and restart. Login data, invite code and settings carry over. If you use the official server, run `/p2p consent` once.
